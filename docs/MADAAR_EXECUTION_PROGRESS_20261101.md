## المخرجات البرمجية
- BusinessCommitment متعدد المنشآت والأدوار: توريد المورد، تحصيل العملاء، ومهام الخدمة؛ موعد وحالة وسبب وسجل تدقيق.
- يضاف تعهد التحصيل مع المستحق داخل نفس المعاملة؛ وينتهي داخليًا عند تسجيل كل تحصيله؛ لا يعني تحققًا بنكيًا.
- يمكن إرفاق موعد التوريد بطلب شراء؛ وعند إكمال الاستلام أو إلغاء الطلب تُحدّث حالة التعهد داخل المعاملة.
- شاشة /commitments مع إدخال موعد توريد من طلب قائم، أو موعد إنجاز خدمة، مع قائمة داخلية ومؤشر تأخير.
- /profit-shield يتابع آخر 30 يومًا من إيراد وتكلفة أصناف البيع والهدر المسجل للصنف المبيع؛ ويعرض المصاريف والرسوم دون إسناد غير موثق.
- حارس نطاق الشركة في APIs والصفحات، وأدوار OWNER/MANAGER/ACCOUNTANT للقراءة، وOWNER/MANAGER لتعديل مواعيد الخدمات والتوريد.

## قيود التنفيذ
- ليس دليلًا على استلام التحويل أو التسليم الخارجي؛ البيانات ذاتية الإدخال.
- أقرب 250 تعهدًا فقط؛ 5000 سطر بيع و2000 حركة هدر حد مؤقت؛ أي تجاوز ظاهر مع تحذير.
- هدر المواد الخام داخل الوصفات لا يُنسب تلقائيًا للمنتج المباع؛ لا توجد محاسبة صافي ربح معتمدة.
- يلزم Migration مجرّب على staging وإجراءات نسخ احتياطي واسترجاع قبل أي نشر.

## غير مكتمل في الرؤية العامة
- الامتثال ZATCA/PDPL، قيد آلي معتمد لكل المصادر وتسويات بنكية متحققة.
- SSO/SCIM وRBAC كامل للأقسام والفروع، أدلة تدقيق غير قابلة للتلاعب، اختبارات اختراق.
- المطاعم متعددة القنوات/شاشة المطبخ/الولاء، تشغيل مصانع BOM/MRP، أوامر الفنيين، أساطيل وWMS متقدم.
- Webhooks وتكاملات بنك/واتساب/متجر مرخصة، منصة عمليات غير متزامنة Outbox، مساعد صوتي/بصري.
- تقارير تجميع شركات وMulti-currency، إدارة حسابات بينية، أحمال مئات الفروع.
- CI/build/typecheck/Prisma staging/E2E لم تثبت بعد؛ GitHub Actions كان مقفولًا بسبب مشكلة فوترة.

## بوابة الإفراج
1. عدم دمج PR #40 أو هذا الفرع أو دفع الوسوم/النشر قبل إصلاح CI.
2. تشغيل npm ci / prisma validate / TypeScript / npm run build / node --test tests/*.test.mjs على Node 24 وPostgreSQL تجريبي.
3. اختبار عزل شركتين ومستخدمين متعددين، التوريد الجزئي والمكتمل، إلغاء طلب، تحصيل جزئي ومكتمل، صلاحيات الفروع.
4. نسخ قاعدة staging احتياطيًا وتجربة استعادة وتطبيق ترحيل Prisma المراجع، ثم اختبار قبول متعدد الأدوار.
