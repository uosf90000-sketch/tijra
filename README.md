# تِجرا — TIJRA

منصة عربية لإدارة تشغيل التاجر الصغير من مكان واحد: المخزون، المبيعات، الموردون، المشتريات الذكية، المحاسبة، الموظفون والرواتب.

## حدود المنتج المعتمدة

- **لا يوجد تمويل أو إقراض** داخل تِجرا.
- **التوصيل ليس جزءًا من المنصة**؛ ترتيبات التوصيل وموعده تبقى مباشرة بين التاجر والمورد.
- المحاسبة ضمن المنتج.
- إدارة الموظفين والرواتب ضمن المنتج.

## ما يعمل الآن

- تسجيل حساب مالك منشأة وتسجيل دخول وخروج بجلسات مخزنة في PostgreSQL وCookie آمنة HttpOnly.
- صلاحيات OWNER / MANAGER / CASHIER / ACCOUNTANT / SUPPLIER، مع عزل كل منشأة عن الأخرى في APIs التشغيلية.
- Dashboard عربي RTL ومتجاوب مبني على بيانات المنشأة الفعلية.
- إضافة المنتجات والرصيد الافتتاحي ونقاط إعادة الطلب، مع سجل حركة مخزون.
- POS فعلي: تسجيل البيع وخصم المخزون وحفظ التكلفة والربح داخل transaction واحدة.
- إضافة الموردين وتسجيل أسعارهم والحد الأدنى للطلب ومقارنة أفضل سعر.
- مشتريات ذكية تنشئ طلبات شراء مجمعة حسب المورد من الأصناف التي وصلت لنقطة إعادة الطلب.
- استلام المشتريات transactionally: الكمية المستلمة فقط، وتحديث متوسط التكلفة المرجح.
- OCR مجاني محلي لفواتير الموردين باستخدام Tesseract بالعربية والإنجليزية، مع استخراج أولي لرقم الفاتورة والرقم الضريبي والإجمالي والضريبة وأسطر محتملة للأصناف.
- إضافة الموظفين ومسيرات رواتب محفوظة.
- محاسبة إدارية مبسطة مبنية على المبيعات وتكلفة البضاعة والمصاريف والرواتب المعتمدة.
- Health check يتحقق من اتصال PostgreSQL فعليًا.
- إعداد Railway عبر `railway.json` مع pre-deploy لتجهيز مخطط قاعدة البيانات.

## الواجهة

الواجهة مستلهمة من أنماط dashboards الحديثة في 21st.dev: هرم بصري واضح، sidebar مجمّع، جداول كثيفة للبيانات، بطاقات KPI محدودة، mobile bottom navigation، وحالات واضحة للمخزون والطلبات. التصميم والكود خاصان بـTIJRA وليس نسخًا مباشرًا من مكوّن بعينه.

## التشغيل محليًا

```bash
npm install
cp .env.example .env
npm run db:generate
npm run db:push
npm run dev
```

ثم افتح `http://localhost:3000/register` لإنشاء أول منشأة.

## الفحص

```bash
npm run check
```

## أهم الـAPI

- `POST /api/auth/register` — إنشاء مالك + منشأة + جلسة.
- `POST /api/auth/login` / `logout` — المصادقة.
- `GET/POST /api/products` — المنتجات والمخزون الافتتاحي.
- `GET/POST /api/suppliers` — الموردون.
- `POST /api/supplier-offers` — أسعار الموردين.
- `POST /api/sales` — البيع وخصم المخزون ذرّيًا.
- `GET/POST /api/purchase-orders` — طلبات الشراء.
- `POST /api/purchase-orders/smart` — إنشاء طلبات ذكية مجمعة حسب المورد.
- `POST /api/purchases/receive` — اعتماد الاستلام وتحديث المخزون والتكلفة.
- `POST /api/ocr/invoice` — OCR للفاتورة، ويتطلب مراجعة بشرية قبل اعتماد الاستلام.
- `GET/POST /api/employees` — الموظفون.
- `GET/POST /api/payroll/runs` — مسيرات الرواتب.
- `GET/POST /api/expenses` — المصروفات.
- `GET /api/health` — فحص الخدمة وقاعدة البيانات.

## Railway

المستودع يحتوي `railway.json`. المطلوب في مشروع Railway هو خدمة التطبيق وخدمة PostgreSQL، ثم جعل `DATABASE_URL` في خدمة التطبيق تشير إلى متغير اتصال PostgreSQL. قبل كل نشر يشغّل Railway `npm run db:deploy`، ثم يبدأ Next.js بـ `npm start` ويستخدم `/api/health` كفحص صحة.

## OCR

النسخة الحالية لا تحتاج مفتاح OCR مدفوع. Tesseract يعمل داخل الخادم ويدعم `ara + eng`. نتيجة OCR ليست اعتمادًا محاسبيًا تلقائيًا؛ المستخدم يراجع الكميات والأسعار قبل تحديث المخزون.

## ملاحظات إنتاجية

- لا تضع كلمات مرور أو مفاتيح أو `DATABASE_URL` حقيقيًا في المستودع العام.
- `prisma db push` مناسب لمرحلة MVP الحالية؛ قبل إدارة تغييرات مخطط إنتاجية طويلة المدى ننقل إلى Prisma migrations منظمة.
- المحاسبة الحالية ملخص إداري وتشغيلي وليست بديلًا عن متطلبات المحاسبة النظامية أو الإقرارات الضريبية.
- الفوترة الإلكترونية/ZATCA ليست ضمن هذا الإصدار حتى يتم تنفيذها كنطاق مستقل واختبارها تنظيميًا.
